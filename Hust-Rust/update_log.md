### 新增特性

1. **Namespace 系统保留命名空间**
   - 全大写命名空间保留给 Hust 系统（RUST、HUST 等）
   - 用户命名空间禁止使用全大写

### 设计决策

1. **全大写保留机制**
   - 系统级：RUST、HUST、STD、IO 等
   - 用户级：禁止全大写，避免冲突
   - 优势：用户与系统命名空间分离，简洁直观

### 示例

```hust
use RUST.std.io.*;   // 导入 Rust IO 桥接
use HUST.math;       // 导入 Hust 数学库

void main() {
    println("Hello");  // RUST.std.io.println
}
```

### 新增特性

1. **Namespace 命名空间完整实现**
   - 基础 namespace 解析：`namespace Name;` 声明，文件最前面
   - 函数注册表：建立 函数名 → 命名空间 映射
   - 调用自动补全：`factorial(5)` → `math.factorial(5)`
   - use 语句细化：`use ns`、`use ns.item`、`use ns.*`、`use ns as alias`
   - 过继模型：类继承时父类移至子类命名空间
   - 嵌套类支持：Outer.Inner 数据结构
   - 访问权控制：public/private 方法级别
   - 分布报告：namespace 文件列表，防止过度分散
   - `.` 分隔符：Hust 用 `.`，Rust 生成 `::`

2. **settings.config 添加 description 字段**
   - 用户自定义工程说明文本
   - 可选，不影响编译

### 设计决策

1. **Namespace 分隔符用 `.`**
   - C#/Java/Go/Python 都用 `.`，承袭性更好
   - Rust/C++ 转译时 `.` → `::`

2. **不支持静态类**
   - 静态类是语法糖，本质是 namespace + 函数
   - Rust/Go 无静态类概念，保持一致

3. **过继模型**
   - 类被继承后，完全归新命名空间所有
   - 原命名空间中的该类不再可用
   - 风险由程序员负责，建议保持命名空间一致

### 设计决策实现

1. **接口实现方法必须 public（跨维度统一拦截族新增）**
   - 原则：私有方法实现公开接口 = 经 trait 路径泄漏（trait 导入即可达，
     实测 42 泄漏案例）——Java/Go 同款强制（weaker access = 编译错误）
   - Rule 1.5 check_interface_impl_visibility：实现接口的类中，
     非 public 方法若为接口成员 → fail-fast 报错并给出修法
     （`public f32 getAverage(...)`）
   - 方法名 snake_case 归一化比对（trait 成员已 snake_case，类方法
     可能 camelCase）
   - 报错正确指向所属接口（HashMap 方法→接口映射）
   - 可见性两层模型（r23 已文档化）：trait 层随接口契约 +
     inherent 层 r26 私有默认 + 同名共存调用优先（inherent）

### 设计决策实现

1. **静态数组不自动转动态（跨维度统一拦截）**
   - 原则：静态即静态，Hust 不提供任何自动静态→动态转换（to_vec 等）
   - Rule 4.6 reject_static_to_vec：拦截静态数组（任意维度）的 .to_vec()
     —— 一维裸调用、多维裸调用、行级链式 m[0].to_vec()（索引链回溯至根）
   - 放行：动态对动态调用（c[0].to_vec()，c 为 i32[][]）不受影响
   - 报错给出正道：push([]) / push(v) 直接构建动态数组
   - 与 const 数组拦截（Rule 4.5）同一思想：不做隐式类型变形，
     语法即语义，形态即声明
