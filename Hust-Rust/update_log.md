# Hust-Rust 更新日志

--------------------
**日期**: 2026-09-11
**版本**: v0.1.13+20260911170824（首次应用多人格式版本号 YYYYMMDDhhmmss）

### 新增特性

1. **静态数组无初始化声明（矩形零值填充）**
   - 多维：`i32[10][10] c;` → `let mut c: [[i32; 10]; 10] = [[0; 10]; 10];`
     类型与零值同循环右向左嵌套（N 维通用），零值按类型（整数0/浮点0.0/bool false）
   - 一维：`i32[5] arr;` → `let mut arr: [i32; 5] = [0; 5];`
   - 完成 N 维双形态设计第一步（设计指引 2026.09.09 第二段）：
     矩形静态 = 带尺寸声明；锯齿动态 = 空维度[] + push/pop

2. **单语句循环体支持**
   - C 风格无花括号写法：`for(i16 i=0; i<3; i++) println!("i = {}", i);`
   - body 类型判定基于 `)` 后首个非空白字符（println 格式串 `"i = {}"`
     中的花括号不再误导路由）；提取消费的结束分号自动补回

### Bug 修复

1. **块更新分支优先级缺陷（V0.1.8 潜伏）**
   - 问题：块更新 `{ count++; i++; }` 含 `++` 时被 `is_postfix` 抢入
     单操作符分支，块内容整体丢弃，导致死循环
   - 解决：块更新判断前置；块内 `var++`/`var--` 转换为 `var += 1`/`var -= 1`

2. **const 数组友好报错（设计决策：数组默认可变，不支持 const）**
   - 新增 Rule 4.5 reject_const_array：拦截 `const i32[2] a` 与 C 风格
     `const i32 a[2]`，fail-fast 给出改写建议与切片替代方案
   - 替代此前产出的非法 `const let mut` 代码

3. **中文字符边界 panic**
   - 字节回退切进多字节字符、`chars().enumerate()` 字符序号误作字节切片
   - 连带修复 bitwise_test.hust

4. **拆离法轮数上限放宽 10 → 32**
   - 每轮剥离至少一层，N 维需 N-1 轮，13 维需 12 轮超旧上限

### 测试结果
- 全套 48/48 通过（含 3/5/7/13 维无初始化极限测试 sum=2^N，13 层嵌套全链路）
- q3/q3_test 交互式练习程序移出测试目录

**日期**: 2026-09-08
**版本**: v0.1.11+20260908

### 新增特性

1. **多维数组声明泛化支持 N 维（N ≥ 2）**
   - `transform_multi_array_decl` 重写：正则捕获维度串 `(?:\[\d+\]){2,}`，不数层数
   - Rust 类型循环构建（最右维最内层）：`i32[2][2][2]` → `[[[i32; 2]; 2]; 2]`
   - 元素 `{`→`[` 替换天然深度无关；一维仍由原规则处理
   - 极限测试：4/6/8 维（至 256 元素）N 层嵌套 for 全链路通过（tests/multi_dim_4/6/8.hust）

2. **install.sh 一键构建安装脚本**
   - release 构建 + 安装至 `~/.local/bin`，自动处理沙箱 CARGO_HOME
   - 新增 `Hust-Rust/howto_build.md`：Linux/Windows 编译安装全英文指南

### Bug 修复

1. **拆离法索引剥离三层及以上收敛失败**
   - 问题：已转换层 `(i) as usize` 的匹配消费了闭括号 `]`，更深层索引失去宿主，
     N≥3 链收敛差一层（`cube[i][j][k]` 的 `[k]` 漏转）
   - 解决：索引正则要求 `[a-zA-Z_]` 开头——已转换层（`(` 开头）不再匹配，
     其 `]` 保留给更深内层

### 测试结果
- 全套 43 个测试：38 通过（基线 35 + multi_dim 3 个），8 个既有失败不变

### Bug 修复

1. **嵌套数组索引漏转 as usize**
   - 问题：`matrix[i][j]` 内层 `[j]` 未转换，Rust 编译报 E0277
   - 解决：`transform_array_indices` 重写为拆离法两阶段（变量名宿主 / `]` 宿主循环剥离）

2. **循环条件 len() 类型不匹配**
   - 问题：`i < dynamic.len()` 中 i32 与 usize 比较报 E0308
   - 解决：新增 `transform_len_comparison`（L1 全串锚定，双向模式），
     `i < arr.len()` → `(i as usize) < arr.len()`
   - 复合条件不自动转（fail-safe），由 rustc 报错，用户 `(usize)` 显式自救
   - 移除旧的 `transform_condition_vars`（逻辑收编进 for 循环转译）

### 重构改进

1. **开发环境迁移至 Linux**
   - 沙箱只读 HOME 场景的 `CARGO_HOME` 方案写入 howto_build.md
   - 新增 r33 语法规则（循环条件 len() 转换）与 len()-1 下溢警示
   - 新增 install.sh、for_ai_agent 跨 AI 协作排查机制

### 测试结果
- all_arrays.hust（含 len() 条件与二维矩阵）全链路通过
- 全套 43 个测试：35 通过（修复前 34），零新增失败

**日期**: 2026-06-23
**版本**: v0.1.10+20260623

### 新增特性

1. **保留用户声明的变量类型**
   - for 循环变量不再硬编码为 usize/i32，保留用户声明的原始类型（i8/i16/i32 等）

2. **数组索引自动适配 Rust**
   - 新增 Rule 18，自动为变量索引添加 `as usize` 转换
   - 示例：`scores[i]` → `scores[(i) as usize]`
   - 字面量索引（如 `scores[5]`）和切片（如 `scores[0..5]`）不受影响

### Bug 修复

1. **递减循环 `i>=0; i--` 支持**
   - 之前自动转 usize 导致 `i>=0` 永远为真、`i=0; i--` 溢出 panic
   - 现在使用用户声明的有符号类型，递减循环正常退出

2. **注释后跟花括号编译错误**
   - 问题：`// 注释}i = i + 1;}` 中 `}` 被行注释吞并
   - 解决：for 循环体多行格式化，更新语句在独立行

**日期**: 2026-05-24
**版本**: v0.1.6+20260524

### 修复内容

1. **for 循环转换优化**
   - 简单条件如 `i < n` 转换为 Rust 原生 `for i in 0..n`
   - 复杂条件如 `(i*i <= n)` 转换为 while 循环

2. **修复 while 循环递增 BUG**
   - 问题：更新语句 `i = i + 1` 未添加到 while 循环体
   - 解决：将更新语句插入 while 循环体的开头

3. **修复转换顺序问题**
   - 问题：`for (i = 2; i*i <= n; i++)` 转换为 `for ((i16 i) = 2; ...)`
   - 原因：变量声明转换在 for 循环转换之后执行
   - 解决：调整转换顺序，for 循环转换优先于变量声明

4. **修复数组声明双分号 BUG**
   - 问题：`i16[4] numbers = {1,2,3,4};` 转换后产生 `;;`
   - 原因：正则表达式未匹配末尾分号
   - 解决：正则改为 `([^}]+)\};` 确保匹配完整声明

### 测试结果
- 质数判断测试通过：2 is true, 17 is true, 25 is false, 97 is true
